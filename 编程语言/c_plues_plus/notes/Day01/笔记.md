### 1.1 链路构建

| 预处理  | g++ -std=c++17 -E main.cpp -o main.i | main.cpp | main.i 预处理后的c++源文本 | 执行 `include`、宏和条件编译等预处理指令  |

| 链接   | g++ main.o -o day01_linked           | main.o   | day01_linked 可执行文件 | 填充重定位的符号地址，合并节、解析符号以及处理库依赖 |
### 1.2 声明与定义
1. 二者分别向编译器提供了什么信息？
声明让编译器知道变量的类型，函数的返回值类型和参数类型；类型决定对象大小，定义负责分配存储空间并可选初始化，函数定义给出函数体
2. 定义对对象和函数分别做什么？
对象定义分配存储空间并可初始化，定义函数为函数提供了函数体
3. 声明与定义各自能否重复出现？
在同一实体中声明可以重复出现，定义不可以重复出现
### 1.3 头文件与源文件
1. 为什么头文件通常只放声明和必要的定义，而不放普通函数、全局变量的定义？
头文件主要价值是共享接口，头文件放普通函数和全局变量定义会导致多个翻译单元重复定义普通函数和全局变量
2. 若一个普通函数定义被两个 `.cpp` 同时包含，链接阶段可能出现什么问题？
多个 `cpp` 各自形成翻译单元，普通函数定义被包含多次会造成同一实体出现多个定义，链接器会报重复定义
3. 包含保护(include guard或 `#pragma once`) 解决什么问题？
包含保护只防止同一翻译单元内重复展开头文件，不能阻止两个不同 `cpp` 各自包含并产生重复定义
### 1.4 命名空间
1. 命名空间解决什么问题？
解决查找歧义和全局名字污染
2. 访问其成员有哪两种常见写法，使用时各有什么风险或取舍？
using namespace 和 namespace::成员名；using会引入对应命名空间中所有可访问的成员，可能导致查找歧义和全局名字污染，namespace::成员名需要重复书写
3. 为什么 `<iostream>` 中的输出对象要写成 `std::cout` ？
限定在 std 命名作用域查找 cout
### 1.5 程序入口
1. `main` 的两种标准签名分别是什么？
int main(); int main(int argc, char** argv);
2. `main` 的返回值表示什么？省略 `return 0;` 是否允许？
程序执行结束的状态；可以
3. 若程序没有 `main` 或出现两个 `main`，链接阶段分别可能怎样？
未解析入口符号；入口符号重复定义

## 4. 三类错误
①非法编译选项 `-st=c++17`；
②缺少分号，编译阶段报错；
③未定义的 `add()`，链接阶段报错。

2.  声明与定义有什么区别？请同时覆盖对象和函数，并说明能否重复出现。
声明让编译器知道变量的类型，函数的返回值类型和参数类型；变量定义提供变量占存储空间的大小，函数定义给出函数体；在同一实体中声明可以重复出现，定义不可以重复出现
3. 为什么头文件通常只放声明和必要定义，而不放普通函数、全局变量的定义？请结合“多个翻译单元”和“链接阶段”说明
