### 一、是什么
C++异常处理是C++语言提供的一种错误处理机制，允许程序在运行出现错误时，通过 `try`、`catch`和`throw`三个关键字将错误信息传递回调用栈，进行异常处理。
简单来说，当程序检测到无法处理的错误时，可以 **抛出** 一个异常对象；程序的控制流会沿着调用栈向上回溯，直到找到能够 **捕获** 并处理这个异常的代码；如果始终没有找到，程序将终止。
C++的异常处理机制支持异常的重新抛出、自定义异常体系，并且标准库提供了以 `std::exception` 为基类的异常类层次结果。

---
### 二、为什么需要它
#### 2.1 传统错误处理方式的缺陷
在C语言中，错误处理主要依赖两种方式：`assert` 终止程序，或返回错误码。这些方式存在明显问题：
- **容易忽略错误检查**：调用方可能忘记检查返回值，导致程序在错误状态下继续运行，产生不可预知的结果
- **错误信息不充分**：仅凭一个错误码难以传递足够的上下文信息，调试困难
- **代码可读性差**：大量的错误码检查逻辑混杂在正常业务逻辑中，干扰代码的清晰度
#### 2.2 异常处理的核心优势
- **强制处理错误**：未捕获的异常会终止程序，迫使开发者必须正视错误
- **分离错误检测与处理**：异常可以在检测错误的代码与处理错误的代码之间建立明确的分离，中间函数可以透明地让异常传播
- **自动资源清理**：异常抛出后，栈展开机制会自动销毁沿途的所有局部对象，确保资源被正确释放
- **信息丰富**：异常是对象，可以携带详细的错误描述和上下文信息

### 三、核心语法与分类
#### 3.1 三个核心关键字
| 关键字     | 作用                                               |
| ------- | ------------------------------------------------ |
| `try`   | 标记一个可能抛出异常的代码块，其中的代码被称为"保护代码"                    |
| `throw` | 抛出一个异常对象。当问题出现时，程序通过 `throw` 来发出异常信号             |
| `catch` | 捕获 `try` 块中抛出的异常并进行处理，可以有多个 `catch` 分支来匹配不同类型的异常 |
#### 3.2 异常的类型
C++ 中可以抛出 **任意类型** 的对象 -- 基本类型、指针、类对象均可。但在实际工程中， **强烈建议抛出继承自** `std::exception` **或其派生类的对象**，以便统一处理
标准库提供异常类体系 (定义在 `<stdexcept>` 中)：

| 异常类                     | 描述                 |
| ----------------------- | ------------------ |
| `std::exception`        | 所有标准异常的基类          |
| `std::runtime_error`    | 运行时错误 (如溢出、文件打开失败) |
| `std::logic_error`      | 逻辑错误 (程序员失误导致)     |
| `std::out_of_range`     | 容器越界访问             |
| `std::invalid_argument` | 参数无效               |
| `std::length_error`     | 容器过长引发的错误          |
#### 3.3异常抛出与捕获规则
- 异常是通过 **类型** 来匹配的，`throw` 表达式的值本身没有实际意义， **类型才是决定哪个**`catch` **被激活的关键**
- 被选中的 `catch` 是调用链中 **与异常类型匹配且距离抛出位置最近** 的那一个
- `catch(...)` 可以捕获任意类型的异常，但无法获取具体的错误信息，通常用作最后的"兜底"
- 派生类异常可以被基类 `catch` 捕获 -- 这一特性在实际项目中非常实用
- **异常的重新抛出**：在 `catch` 块中使用 `throw;` (不带表达式) 可以将当前捕获的异常原样重新抛出，传递给外层的 `catch` 处理。注意 `throw e;` 会拷贝异常对象，可能导致派生类信息丢失 (切片问题)

### 四、典型应用场景
#### 4.1 构造函数失败
构造函数没有返回值，无法通过返回错误码来报告失败。抛出异常是构造函数报告失败的标准方式。
#### 4.2 文件操作与资源管理
文件打开失败、内存分配失败等场景，异常配合 [[RAII | RAII(资源获取即初始化)]] 可以确保资源不会泄露
#### 4.3 容器越界访问
标准容器的 `at()` 方法在索引越界时会抛出 `std::out_of_range` 异常
#### 4.4 网络请求与外部服务调用
网络超时、服务不可用等运行时错误，适合用异常向上传递错误信息
#### 4.5 大型项目的统一错误处理
在实际项目中，通常会定义一套继承自统一基类的一场体系，各模块抛出不同类型的派生异常，外层通过捕获基类来同意标准

### 五、完整示例
``` c++
#include <iostream>
#include <stdexcept>
#include <string>

// 自定义异常类
class MyException : public std::runtime_error {
public:
    explicit MyException(const std::string& msg)
        : std::runtime_error(msg) {}
};

// 可能抛出异常的函数
int divide(int a, int b) {
    if (b == 0) {
        throw MyException("除数不能为零");
    }
    return a / b;
}

// 使用 RAII 管理资源
class FileGuard {
public:
    explicit FileGuard(const std::string& filename) {
        m_file = fopen(filename.c_str(), "r");
        if (!m_file) {
            throw MyException("打开文件失败: " + filename);
        }
        std::cout << "文件打开成功" << std::endl;
    }

    ~FileGuard() {
        if (m_file) {
            fclose(m_file);
            std::cout << "文件关闭成功" << std::endl;
        }
    }
private:
    FILE* m_file;
};

// 演示异常重新抛出
void processData() {
    try {
        FileGuard fg("data.txt");
        int result = divide(5, 0);
        std::cout << "5 / 0 = " << result << std::endl;
    } catch (const MyException& e) {
        std::cerr << "局部处理: " << e.what() << std::endl;
        throw; // 重新抛出，让上层处理
    }
}

int main() {
    try {
        processData();
    } catch (const std::exception& e) {
        std::cerr << "顶层捕获: " << e.what() << std::endl;
        return -1;
    } catch (...) {
        std::cerr << "未知异常" << std::endl;
        return -1;
    }

    return 0;
}
```
**运行结果**：
``` txt
文件打开成功
文件关闭成功
局部处理: 除数不能为零
顶层捕获: 除数不能为零
```
